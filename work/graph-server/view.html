1. Nguyên tắc ghép Graph với JEV từ TypeSafe

TypeSafe official skill mô tả System One/JEV như programmable common sense: code giữ workflow, hard rules, lookup, calculation và execution; JEV chỉ cung cấp judgment semantic có kiểu.

  1. Graph/schema tạo không gian hợp lệ: entity type, relation type, cardinality, direction, domain/range, validity/provenance.
  2. Code lọc luật cứng trước: điều gì xác định được bằng dữ liệu/rule thì không gọi JEV.
  3. JEV chỉ xử lý bounded semantic: choice, noul, score; có none/no-match khi candidate có thể thiếu.
  4. Probability/confidence không phải quyền ghi: threshold phải đánh giá trên dữ liệu Incomex; thiếu evidence/không chắc → reasoning model hoặc human review.
  5. Canonical graph chỉ nhận edge sau policy gate: lưu source, actor, time learned, valid-from/valid-to và loại bằng chứng.

Điều này khớp bài công bố JEV của Diogo Almeida ngày 15/09/2026: workflow tin cậy thường gồm nhiều judgment nhỏ, độc lập/decomposed; branching cuối cùng nằm trong domain-specific code thay vì model sinh prose tự do.

9. Acceptance tests đề xuất — chưa phải RUN

  1. Finite schema: relation ngoài schema phải reject hoặc giữ riêng dạng proposal.
  2. Provenance: mỗi canonical edge truy được source/actor/time và phân biệt observed / deterministic / JEV / LLM inference.
  3. Temporal: fact thay đổi phải giữ lịch sử, query current và point-in-time.
  4. Entity resolution: alias/tên gần nhau bắt buộc no-match + review path.
  5. JEV boundary: không tạo relation type mới, bypass hard rule hay tự cấp quyền ghi.
  6. Calibration: threshold đo trên labeled Incomex cases, không lấy demo threshold làm universal.
  7. Code graph: import/call/test dependency so với compiler/LSP ground truth; semantic labels tách riêng.
  8. Resource: đo RAM/CPU/IO/disk/index/query trên VPS trước khi chốt service count.
  9. Rollback: mỗi candidate có đường remove/rollback không làm hỏng Postgres/runtime hiện hữu.
